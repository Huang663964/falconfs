# DiskCache Evict / Unlink NVMe 性能测试结果

本文记录当前 lease 保护方案在 NVMe 服务器上的最终一键测试结果。测试步骤见 [性能测试步骤文档.md](性能测试步骤文档.md)。

最终结果以 GitHub commit comment `188808661` 中的 `final_report.log` 为准；后续 comments 是同一轮 monitor/log 附录。

当前方案：DiskCache evict 选中可回收 cache item 后，先按 `path + expected_inode` 调用服务端 `UNLINK_IF_INODE_MATCH` 做 metadata 条件删除。metadata 侧会检查 inode 是否仍匹配，并检查该 inode 是否存在未释放 lease；只有 metadata 条件删除成功，才继续删除本地 cache 文件并从 DiskCache 索引中移除。path 不存在或 inode 不匹配按 success/no-op 处理，lease 冲突返回失败并保留本地 cache。

## 3. Python internal API 结果总览

业务路径为 Python internal API：Python 进程通过 `pyfalconfs.Client` 调用 `_pyfalconfs_internal` C 扩展，最终进入 `FalconCreate/FalconWrite/FalconFlush/FalconClose/FalconUnlink/FalconRead`，不经过 FUSE 挂载点。

P-RW/P-RWE 使用 pinned-read 口径：先预创建每个 reader 256 个读热集文件，reader 在混合阶段开始前执行 `Open + warmup Read`，使读热集进入 DiskCache 并被 pin；随后 reader 在 120s 窗口内循环读已打开 fd，writer 写新文件，P-RWE 通过 writer 写入推动后台 `DiskCache::Cleanup()`。

| 编号 | 场景 | 进程/并发 | 读吞吐 | 写吞吐 | 删除/evict 吞吐 | p99 延迟 | 错误 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| P-1 | 纯写 | 4 writer | N/A | 540.19 files/s, 1080.38 MiB/s | N/A | 写 8.91ms | 0 |
| P-2 | 预创建后纯 unlink | 4 create + 4 unlink | N/A | create 534.60 files/s, 1069.20 MiB/s | unlink 1223.44 files/s, 2446.87 MiB/s | unlink 13.95ms | 0 |
| P-3 | 写触发后台 evict | 4 writer + cleanup | N/A | 411.76 files/s, 823.53 MiB/s | cleanup 328.06 files/s, 656.12 MiB/s; remove 850.48 files/s, 1700.95 MiB/s | 写 49.42ms | 0 |
| P-5 | 持续边写边 unlink | 4 writer + 4 deleter | N/A | 375.50 files/s, 751.00 MiB/s | unlink 1185.39 files/s, 2370.79 MiB/s | 写 56.44ms; unlink 24.26ms | 0 |

## 6. Evict metadata 条件删除

final report 中各 listener 退出统计均为 `failed=0`、`dropped=0`。可见行的单 listener 统计为 `attempted=822`、`processed=822`、`succeeded=822`，p99 范围约 `9.40ms - 20.80ms`。本轮 summary 的 listener 行数与 cleanup 合计文件数不完全对齐，正式引用时以 cleanup 聚合的 `failed/scanned=0/10672` 和业务 `errors=0` 作为主结论。

## 7. 最终结论

| 结论项 | 说明 |
| --- | --- |
| 功能正确性 | P-1/P-2/P-3/P-5/P-R1/P-RW/P-RWE 全部 `errors=0`。 |
| evict 触发 | `16GiB / 0.90` 配置下，P-3 和 P-RWE 均触发后台 evict。 |
| lease 保护 | metadata 条件删除失败或 lease 冲突时，DiskCache 保留本地 cache 和索引；本轮未出现业务错误。 |
| 删除能力 | P-2 unlink `2446.87 MiB/s`，P-5 unlink `2370.79 MiB/s`，evict remove-only `2784.15 MiB/s`，删除侧吞吐高于写入侧。 |
| evict 对写影响 | P-3 写触发 evict 时 writer `823.53 MiB/s`，比 P-1 纯写 `1080.38 MiB/s` 下降约 `23.8%`；P-RWE writer active `850.55 MiB/s`，比 P-RW writer active `889.21 MiB/s` 下降约 `4.3%`。 |
| pinned 读写混合 | P-RWE reader `3565.65 MiB/s`，与 P-RW reader `3543.35 MiB/s` 同级，读路径没有因 evict 出现错误。 |
| 主要瓶颈 | evict 完整 cleanup 吞吐低于 remove-only，主要额外开销来自 cleanup 调度、metadata 条件 unlink 和 Falcon 写路径本身；本地 remove 不是当前唯一瓶颈。 |
